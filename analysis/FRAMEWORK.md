# 売上分析フレームワーク（Marni リテール）

実データ到着前の準備フェーズとして、分析の設計図を定義する。実データが `data/` に届き次第、
このフレームワークに沿って `analyze.py` を実行し、最終的にMarniブランドテンプレートのPPTXへ落とし込む。

## 0. 想定読者・アウトプット

- **想定読者**: 本社・経営会議（HQ / エグゼクティブ）
- **時間軸の主従**: **累計（YTD / H1など）を主軸**とし、単月の振れではなく累計トレンドで判断する。月次推移は補助情報として累計の裏付けに使う（単月のノイズで意思決定を誤らせない設計）
- **最終アウトプット**: Marniブランドテンプレートの PPTX（別チャット＝司令チャットが作成）。本分析はそのための数値・チャート・メッセージ（So What）を提供する

## 1. 売上分解式

```
Revenue = Traffic × CVR × ATV
ATV     = UPT × AUR
```

| 指標 | 定義 | 悪化/改善の判定ルール |
|---|---|---|
| Traffic | 来店客数（入店数） | 累計の前年比・計画比が -X%以上のマイナスで「悪化」。閾値の目安: ±5%未満=横ばい, -5%〜-15%=要注意, -15%超=重大 |
| CVR | 購買率（Transaction / Traffic） | 累計のCVR pt差（前年比/計画比の差分pt）で判定。目安: ±1pt未満=横ばい, -1〜-3pt=要注意, -3pt超=重大 |
| ATV | 客単価（Sales / Transaction） | 累計の前年比・計画比のマイナス幅で判定（Traffic/CVRと同様の閾値） |
| UPT | 買上個数（Units / Transaction） | ATV変動のうち「点数要因」を特定するための補助指標 |
| AUR | 平均単価（Sales / Units） | ATV変動のうち「単価要因」を特定するための補助指標 |

**寄与度分解の考え方**：累計Revenueの前年差／計画差を Traffic要因 / CVR要因 / ATV要因（さらにUPT要因・AUR要因）に
**金額（円）ベース**で分解し、どの要素が何円の差を生んでいるかを特定する（対数差分近似 or 順次代入法のいずれかで実装）。
経営会議向けには「％」だけでなく「円」で語れることを必須とする。

## 2. 分析軸（累計を主軸、月次は補助）

**主軸（経営会議で必ず提示）**
1. **累計サマリー** — YTD/H1のRevenue実績、対前年（金額・%）、対計画（金額・%）を最上位指標として提示
2. **累計ギャップ要因分解** — 累計Revenueの対前年差・対計画差を、KPI要因（Traffic/CVR/ATV）× 店舗 × カテゴリの3方向で金額分解
3. **店舗ランキングとドライバー** — 累計ベースの上位・下位店舗ランキングに加え、各店舗の変動が Traffic起因／CVR起因／ATV起因のどれかを付記
4. **経営論点（Decision Points）** — 上記から機械的に絞り込んだ3〜5個の論点リスト（詳細は4章）

**補助軸（累計の裏付け・深掘り用）**
5. **月次推移** — 累計トレンドが月別にどう積み上がっているか（急な悪化月の有無、季節性との区別）
6. **百貨店 vs 路面店** — チャネル種別ごとの累計KPI比較（構造的な差異の把握）
7. **顧客区分（New / Loyal / Lost）** — 累計ベースの客数構成・売上構成の変化、Lost顧客の離脱要因仮説
8. **前年比・計画比** — 全軸に共通で付与する比較レイヤー（金額・%両方を常にセットで出す）

## 3. 要注意店舗の機械的抽出ルール

以下のスコアリングを店舗ごとに**累計ベース**で算出し、上位N店舗（またはスコア閾値超）を「要注意店舗」としてフラグする。

```
risk_score = w1 * max(0, -YTD_YoY_Revenue_pct)
           + w2 * max(0, -YTD_vsPlan_Revenue_pct)
           + w3 * max(0, -YTD_YoY_Traffic_pct)
           + w4 * max(0, -YTD_YoY_CVR_pt)
           + w5 * max(0, -YTD_YoY_ATV_pct)
           + w6 * Lost顧客比率の増加pt（累計）
```

- 初期重み案: w1=0.3, w2=0.3, w3=0.15, w4=0.1, w5=0.1, w6=0.05（データ到着後に調整）
- 追加条件: 累計Revenue規模が一定以上（ロングテールの小規模店を上位に出さないための下限フィルタ）
- 出力: 店舗名、risk_score、主要因（Traffic/CVR/ATVのうちどれが最大寄与か）、累計前年差（円・%）、累計計画差（円・%）

## 4. 経営論点（Decision Points）の判定ロジック

経営会議では「全店舗・全カテゴリの詳細」ではなく、**意思決定すべき論点3〜5個**に絞って提示する。以下の優先順位で抽出する。

1. **インパクト最大の要因** — 累計ギャップ要因分解（3章）で金額寄与が最も大きい上位1〜2要因（例:「路面店のTraffic減が▲◯◯円で最大要因」）
2. **要注意店舗の共通パターン** — risk_score上位店舗に共通するドライバー（例: 上位5店中4店がCVR起因→接客・在庫要因を疑う論点）
3. **計画未達が構造的か一時的か** — 月次推移（補助軸）を見て、未達が特定月に集中しているか、累計を通じて継続しているかを判定。継続的な場合は論点として優先度を上げる
4. **顧客基盤の毀損兆候** — Lost顧客比率が累計で前年より一定pt以上悪化している場合、単なる売上KPIでは見えない中期リスクとして論点化
5. **打ち手の有無で足切り** — 店舗側の努力で改善余地が薄い外部要因（立地閉鎖・改装等）のみに起因する論点は経営論点から除外し、対応可能な論点を優先

上記で抽出された論点候補にスコア（インパクト金額 × 対応可能性）を付け、上位3〜5件を最終的な経営論点として出力する。

## 5. スライド想定チャート一覧（PPTX 1枚 = 1メッセージ）

各チャートは「そのスライドで言い切るメッセージ（So What）」を1文添えて渡す。司令チャット側でPPTX化する際、このSo Whatをスライドタイトル／見出しに使う想定。

| # | チャート | 形式 | So What（スライドで言い切るメッセージ） |
|---|---|---|---|
| 1 | 累計Revenueサマリー（対前年・対計画、金額と%） | KPIタイル/カード | 「上期累計は計画比◯%（◯円)未達／達成」で結論を即示す |
| 2 | 累計Revenueギャップのウォーターフォール（Traffic/CVR/ATV要因、金額） | ウォーターフォールチャート | 「ギャップ◯円のうち最大要因は◯（◯円)」と要因を一意に特定する |
| 3 | 月次Revenue推移（累計線に対する月次内訳、前年重ね） | 折れ線＋累計線の複合グラフ | 「未達は特定月の一時要因ではなく、通期を通じた構造的な傾向」等、単月/構造の別を示す |
| 4 | 店舗ランキング×ドライバー（上位・下位、色分けでTraffic/CVR/ATV起因） | 横棒グラフ | 「下位店舗の大半はCVR起因＝接客/在庫の論点」等、共通ドライバーを示す |
| 5 | 要注意店舗ランキング（risk_score上位、累計） | 横棒グラフ | 「即対応が必要な店舗はこの◯店」と対象を絞り込む |
| 6 | 百貨店 vs 路面店 累計KPI比較 | グループ棒グラフ（Traffic/CVR/ATV） | 「チャネル間の差は構造要因か、施策要因か」を切り分ける |
| 7 | カテゴリ別ギャップ寄与（金額、当年 vs 前年/計画） | 積み上げ棒グラフ/ウォーターフォール | 「ギャップの◯％は特定カテゴリに集中」と資源配分の論点を示す |
| 8 | 顧客区分別（New/Loyal/Lost）累計構成と前年差 | 積み上げ棒グラフ | 「Lost顧客比率が前年比◯pt悪化＝顧客基盤の毀損リスク」を示す |
| 9 | 累計計画比達成率ヒートマップ（店舗×月） | ヒートマップ | 「未達が特定の時期・店舗に集中しているか」を一目で示す |
| 10 | 経営論点サマリー（3〜5件、インパクト金額付き） | テキスト＋インパクト金額の一覧 | 「経営として意思決定すべき論点はこの3〜5点」とクロージングする |

## 6. 実装メモ

- 列名はソースにより変わる想定のため、`analyze.py` の `COLUMN_MAP` で正規化してから集計する。
- 累計（YTD/H1）の期間定義（会計年度の起点、上期の区切り月）はデータ到着後に確認して固定する。
- 前年比較には日付軸の週定義（ISO week等）を揃える必要がある。データ到着後に確認。
- 百貨店/路面店、New/Loyal/Lost の区分定義もデータ側のマスタに依存するため、到着後にマッピングを確定する。
- ギャップ要因分解・ランキングのドライバー判定は「金額」を一次出力とし、「%」は補足として併記する（経営会議では金額感が優先されるため）。
