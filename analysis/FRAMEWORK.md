# 売上分析フレームワーク（Marni リテール）

実データ到着後、`data/`（コレクション26ドア基準）を用いて `analyze.py` で集計し、`FINDINGS.md` にまとめた。
本ファイルはその分析設計図。最終的にはMarniブランドテンプレートのPPTXへ落とし込む想定（別チャット＝司令チャットが担当）。

## 0. 想定読者・アウトプット・対象範囲

- **想定読者**: 本社・経営会議（HQ / エグゼクティブ）
- **時間軸の主従**: **累計（H1）を主軸**とし、単月の振れではなく累計トレンドで判断する。月次推移は補助情報として累計の裏付けに使う
- **最終アウトプット**: Marniブランドテンプレートの PPTX（司令チャットが作成）。本分析はそのための数値・チャート・メッセージ（So What）を提供する
- **対象範囲（最重要）**: 「コレクション26ドア」＝ Retail Store + Retail Concession のみ。MARNI MARKET系（上期¥162M）・Flower Café・POP UP／EVENT・Outlet／Online／卸(OTHER)は含まない。**この範囲の数字を「全社売上」と呼ばない**。必ず「26ドア（コレクション）ベース」と明記する
- **通貨**: 円建て。`store_clienteling_kpi_2025.csv` のみEUR建て・29拠点+Outlet3と対象範囲が異なるため、他CSVと混ぜず単独ページで扱う（通貨・範囲を明記すること）

## 1. 売上分解式（実データの制約を反映）

利用可能なデータには**入店客数（Traffic）も購買率（CVR）も存在しない**。実際に使える分解は以下のみ:

```
Net売上 = TR(客数) × ATV
ATV     = UPT(買上点数) × AP(1点単価)
```

TR(客数)は「購買客数（トランザクション数）」であり、来店したが購入しなかった客数は含まない。したがって
「客数減少が集客の問題か転換率の問題か」は本データでは切り分けられない（データの限界としてFINDINGS.mdに明記）。

| 指標 | 定義 | 悪化/改善の判定ルール |
|---|---|---|
| TR(客数) | 購買客数（トランザクション数） | 累計の前年比が -X%以上のマイナスで「悪化」。目安: ±5%未満=横ばい, -5%〜-15%=要注意, -15%超=重大 |
| ATV | 客単価（Net売上 / TR） | 累計の前年比のマイナス幅で判定（TRと同様の閾値） |
| UPT | 買上点数（数量 / TR） | ATV変動のうち「点数要因」を特定するための補助指標 |
| AP | 1点単価（Net売上 / 数量） | ATV変動のうち「単価要因」を特定するための補助指標 |

**寄与度分解の考え方**：累計Net売上の前年差を TR要因 / ATV要因（さらにUPT要因・AP要因）に**金額（円）ベース**で分解する
（順次代入法。実装は`analyze.py`の`analyze_tr_atv_decomposition()`参照）。経営会議向けには「％」だけでなく「円」で語ることを必須とする。
**比較軸は対前年（vsLY）のみ**。予算（Budget）データが存在しないため、対計画・達成率は算出できない（`store_clienteling_kpi_2025.csv`のBDG列は年間予算だがEUR建て・対象範囲が異なるため使用不可）。

## 2. 分析軸（累計を主軸、月次は補助）

**主軸（経営会議で必ず提示）**
1. **累計サマリー** — H1のNet売上実績、対前年（金額・%）を最上位指標として提示
2. **累計ギャップ要因分解** — 累計Net売上の対前年差を、TR要因/ATV要因（UPT・AP内訳）× 店舗 × カテゴリの3方向で金額分解
3. **店舗ランキングとドライバー** — 累計ベースの店舗を TR×ATV の増減で4象限に分類し、上位・下位のドライバーを付記
4. **経営論点（Decision Points）** — 上記から機械的に絞り込んだ3〜5個の論点リスト（詳細は4章）

**補助軸（累計の裏付け・深掘り用）**
5. **月次推移** — 累計トレンドが月別にどう積み上がっているか（急な悪化月の有無、セール月/プロパー月の傾向確認。ただし単純な二分法が常に成立するとは限らない点に注意）
6. **顧客区分（New / Existing、購入金額階層、Lost）** — 累計ベースの客数構成・売上構成の変化、Lost顧客の離脱による金額インパクト
7. **カテゴリ・品番構造** — RTW/Bags/Footwear等の構成比変化と、品番グループ別の増減額
8. **インバウンド** — 国別の売上・客数・客単価の変化

※「百貨店 vs 路面店」軸は`store_master_list.csv`の業態列（SIS/DPS）を使えば分類自体は可能だが、今回の8分析では未実施（今後の深掘り候補）。

## 3. 要注意店舗の機械的抽出ルール（Traffic/CVR/予算を使わない再定義）

Traffic・CVR・予算データが存在しないため、以下の指標のみでスコアリングする。

```
risk_score = w1 * max(0, -Net_vsLY)
           + w2 * max(0, -TR_vsLY)
           + w3 * max(0, -FP売上_vsLY)
           + w4 * max(0, MD構成比の悪化(=拡大)pt ÷ 100)
```

- 重み: w1=0.35, w2=0.25, w3=0.25, w4=0.15（`analyze.py`の`analyze_store_quadrant_and_risk()`に実装済み）
- 対象: 新規オープン店（渋谷パルコ1F、2025年5月オープン）は前年同期比較が成立しないため除外
- 出力: 店舗名、risk_score、TR×ATVの象限（4分類）、Net/TR/ATV/FP売上のvsLY、MD構成比変化pt

## 4. 経営論点（Decision Points）の判定ロジック

経営会議では「全店舗・全カテゴリの詳細」ではなく、**意思決定すべき論点3〜5個**に絞って提示する。以下の優先順位で抽出する。

1. **インパクト最大の要因** — 累計ギャップ要因分解（1章）で金額寄与が最も大きい上位1〜2要因
2. **要注意店舗の共通パターン** — risk_score上位店舗に共通する象限・ドライバー（例: 上位店の大半がTR減/ATV増＝単価依存）
3. **既存店ベースでの実態検証** — 新規出店の寄与を除いた既存店ベースの数字が、全社数字と乖離していないか
4. **顧客基盤の毀損兆候** — Lost顧客の金額インパクト、新規/既存の内訳、上位顧客層のリテンションが全体指標と逆行していないか
5. **打ち手の有無で足切り** — 店舗側の努力で改善余地が薄い外部要因のみに起因する論点は優先度を下げる

上記で抽出された論点候補にスコア（インパクト金額 × 対応可能性）を付け、上位3〜5件を最終的な経営論点として出力する（実施結果はFINDINGS.md 3章）。

## 5. スライド想定チャート一覧（PPTX 1枚 = 1メッセージ）

各チャートは「そのスライドで言い切るメッセージ（So What）」を1文添えて渡す。司令チャット側でPPTX化する際、このSo Whatをスライドタイトル／見出しに使う想定。

| # | チャート | 形式 | So What（スライドで言い切るメッセージ） |
|---|---|---|---|
| 1 | 累計Net売上サマリー（対前年、金額と%） | KPIタイル/カード | 「H1累計は前年比+0.3%（+7.0百万円）とほぼ横ばい」で結論を即示す |
| 2 | 累計Net売上ギャップのウォーターフォール（TR要因/ATV要因、金額） | ウォーターフォールチャート | 「TR要因▲239百万円をATV要因+246百万円が相殺」と要因を一意に特定する |
| 3 | 既存店ベース vs 全社（渋谷パルコ1F込み・除き） | 比較棒グラフ | 「既存25ドアだけなら売上-1.4%・TR-12.9%で実質減収」を示す |
| 4 | 店舗×TR/ATV 4象限マップ | 散布図（象限区切り） | 「25店中20店がTR減/ATV増＝単価依存で客数減を補う構造」を示す |
| 5 | 要注意店舗ランキング（risk_score上位） | 横棒グラフ | 「即対応が必要な店舗はこの10店」と対象を絞り込む |
| 6 | FP/MD収益の質（差額のウォーターフォール） | ウォーターフォールチャート | 「FP-114百万円をMD+121百万円が穴埋め＝セール依存の進行」を示す |
| 7 | カテゴリ・品番別ギャップ（金額） | 積み上げ棒グラフ/ウォーターフォール | 「バッグ不振はShopping_Bag/Shoulder_Bagに集中、Handbagsは増加」と資源配分の論点を示す |
| 8 | 顧客基盤（新規/既存TR差分の金額換算、Lost金額） | 積み上げ棒グラフ | 「新規顧客減少の金額影響が既存顧客増加の約9倍」を示す |
| 9 | 顧客リテンション（全体 vs 50万円以上顧客） | 折れ線（2系列） | 「全体は改善、上位顧客は悪化」という逆行を一目で示す |
| 10 | 経営論点サマリー（3〜5件、事実→示唆→意思決定） | テキスト＋インパクト金額の一覧 | 「経営として意思決定すべき論点はこの5点」とクロージングする |

## 6. 実装メモ・データの限界（要点。詳細はFINDINGS.md 4章）

- 実データは店長会資料由来の**集計済みサマリーCSV**（取引明細ではない）のため、`analyze.py`は店舗別・カテゴリ別などのCSVを個別に読み込む構成にした（当初想定していた「日次取引データ→pandas groupbyで集計」という設計は使わず、`COLUMN_MAP`方式は本データには不要だった）。
- 予算（Budget）データなし、Traffic/CVRデータなし、DSR（日次）相当データなし。
- 対象は「コレクション26ドア」限定。`store_clienteling_kpi_2025.csv`はEUR建て・29拠点+Outlet3で対象範囲が異なるため未使用。
- 要因分解（TR×ATV、UPT×AP）は順次代入法によるもので、代入順序を変えると金額配分が変わりうる近似値。
- 店舗名の表記ゆれあり。`store_master_list.csv`のRBOコードで名寄せ可能だが自動結合キーは未作成。
